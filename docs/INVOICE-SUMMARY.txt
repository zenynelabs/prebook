2. UNDERSTANDING YOUR REQUIREMENT
--------------------------------------------------------------------------------

Based on our discussions, the system must address the following:

  1. ONE WEBSITE, NOT THREE.
     You already own preebooking.com. You want Crackers, Clothing and Real
     Estate to live as sections of the same site, opened from the main menu -
     one login for the customer, one admin panel for you, one hosting bill to
     pay.

  2. CRACKERS AND CLOTHING ARE SHOPS.
     Customers browse a catalogue, filter by category and price, add to cart
     and place an order. Crackers need safety information and festival packs;
     Clothing needs sizes, colours and variants.

  3. REAL ESTATE IS A LEAD PLATFORM, NOT A SHOP.
     Sellers post property listings, you verify each one before it goes live,
     and buyers request site visits - with the seller's phone number never
     shown to the buyer.

  4. YOU CONTROL EVERYTHING FROM ONE ADMIN PANEL.
     Products, stock, orders, property listings, verification and customers,
     with separate staff logins.

  5. IT MUST WORK ON PHONE, TABLET AND DESKTOP, and be findable on Google.

  6. IT MUST BE BUILT SO NEW BUSINESS SECTIONS CAN BE ADDED LATER,
     without a rebuild.


--------------------------------------------------------------------------------
3. PROPOSED SOLUTION
--------------------------------------------------------------------------------

We propose a single connected platform delivered in two parts:

  PUBLIC WEBSITE (preebooking.com)
    One landing page showing every business section, with a menu to move
    between Crackers, Clothing and Real Estate. Used by your customers,
    buyers and sellers.

  ADMIN PANEL (WEB)
    A role-based back office used by you and your staff to manage products,
    stock, orders, property verification, site visits and customers across
    all three sections.

Because all three sections share one website and one login, the customer
experience is unified and the running cost stays that of a single site. If one
business later grows into a separate company, it can be moved to its own
subdomain without rebuilding anything.

3.2 HOW AN ORDER WORKS - CRACKERS & CLOTHING
- - - - - - - - - - - - - - - - - - - - - - -

  STEP 1 - BROWSE
    Customer opens preebooking.com, picks a section, filters by category /
    type / price, checks live stock.

  STEP 2 - BUY
    Adds items to cart, enters delivery address, confirms the order
    (Cash on Delivery / offline payment).

  STEP 3 - YOU RECEIVE IT
    Order appears in the admin panel as "Pending" and an alert is sent to you.

  STEP 4 - FULFIL
    You move the order through the pipeline; the customer sees the status
    live. Order is delivered and payment collected directly.


3.3 HOW A SITE VISIT WORKS - REAL ESTATE
- - - - - - - - - - - - - - - - - - - - -

  STEP 1 - LIST
    Seller posts a property with photos and details; it stays "Pending" and is
    not publicly visible.

  STEP 2 - VERIFY
    You approve or reject the listing from the verification queue; only
    approved listings go live.

  STEP 3 - REQUEST
    Buyer browses approved listings and requests a site visit with a preferred
    time.

  STEP 4 - COORDINATE
    You receive the request and coordinate the visit offline. The seller's
    contact is never shown to the buyer.

4. SCOPE OF WORK
--------------------------------------------------------------------------------

The following is the complete, agreed scope of this engagement. Anything not
listed here is treated as outside scope (see Section 5).


4.1 WEBSITE & BUSINESS SECTIONS

  - A single landing page showing all three business sections, with a menu to
    open each one.
  - Crackers, Clothing and Real Estate each run as a section of the same
    website.
  - Mobile-first responsive design - works properly on phone, tablet and
    desktop.
  - Basic SEO - clean page titles, sitemap, structured data, server-rendered
    pages.
  - Built so further business sections can be added later as new sections.


4.2 CRACKERS & CLOTHING STORE

  - Product catalogue with its own categories per section (Crackers:
    sparklers, flower pots, rockets, gift boxes · Clothing: men, women, kids,
    accessories).
  - Product listing with filters (type, category, price) and search.
  - Product detail page - photo gallery, price, description; safety
    information for crackers; size and colour variants with a size chart for
    clothing.
  - Festival packs / curated bundles for Diwali and similar occasions.
  - Shopping cart with quantity control.
  - Checkout with delivery address and order confirmation (Cash on Delivery /
    offline payment).
  - Live stock indicators; order status visible to the customer.


4.3 REAL ESTATE SECTION

  - Seller area to post and manage own listings (land, house, apartment) with
    photos.
  - Admin verification queue - listings stay hidden until approved or
    rejected.
  - Public browse of approved listings with filters (type, district, price).
  - Site-visit request flow - buyer submits a preferred time; admin tracks
    status (new / confirmed / completed / cancelled).
  - CONTACT PRIVACY - the seller's phone number is never shown to buyers.


4.4 CUSTOMER ACCOUNTS

  - Sign up and login by email/password or Google.
  - Customer dashboard - my orders, saved delivery address, profile.
  - Site-visit requests for Real Estate while logged in.


4.5 ADMIN PANEL

  - Secure login with role-based access for you and your staff.
  - PRODUCTS - add / edit / delete, upload photos, set price, stock and
    variants.
  - ORDERS - view and manage the order pipeline; update status.
  - REAL ESTATE - approve / reject listings; view and manage site-visit
    requests.
  - CUSTOMERS - view registered customers.
  - ALERTS - notification on new orders and new site-visit requests.


4.6 CORE BUSINESS LOGIC

  - All money stored and calculated as integer paise - no floating-point
    rounding errors on totals, GST or discounts.
  - Stock decremented on order placement; sold-out and low-stock states
    reflect live on the listing and product pages.
  - Property listings are gated behind admin approval - nothing goes public
    unverified.
  - Seller contact details are held server-side and never serialised into any
    buyer-facing response.


4.7 BILLING & PAYMENTS (THIS BUILD)

  - Payments are offline / Cash on Delivery. There is NO online payment
    gateway in this build.
  - The order record is built gateway-agnostic (paymentMethod +
    paymentStatus), so Razorpay or UPI can be added later as a separately
    quoted module without reworking checkout.
  - Order and visit-request alerts are issued to the admin. Customer-facing
    WhatsApp/SMS messaging depends on a third-party service billed to you
    (Section 8).


4.8 TECHNOLOGY

  Public Website (User Interface)
      TanStack Start - server-rendered React, mobile-first, Tailwind CSS
  Admin Panel (Admin Interface)
      Same application, role-gated admin area
  Backend API Service
      Hono on the Bun runtime
  Database Engine
      MongoDB Atlas via Prisma ORM
  Authentication
      Better Auth - email/password + Google, role-based access control
  Media Storage
      Cloudflare R2 - product and property images, presigned direct upload
  Search
      In-app search with filters
  Hosting
      Cloudflare / Vercel with CDN in front

THE EXISTING CODE IS NEXT.JS, NOT TANSTACK START
------------------------------------------------

store/ is a Next.js 16.3.3 App Router application - that was the decision
locked in BUILD_PLAN.md on 31 Aug and built out on 1 Sep. Moving to TanStack
Start + Hono means part of that foundation does not carry across. Worth
knowing before Week 1:

  CARRIES OVER AS-IS
    - store/prisma/schema.prisma - 482 lines, 21 models, 7 enums, validated
    - store/prisma/seed.ts - 517 lines, 20 products + variants + collections
      + promos + pincodes
    - store/lib/ - prisma.ts, money.ts (integer paise), stock.ts, env.ts
      (zod), r2.ts, permissions.ts
    - Better Auth configuration and role model - Better Auth is
      framework-agnostic
    - Design tokens in store/app/globals.css - crimson / cream / gold /
      charcoal, radius 0.75rem
    - Tailwind v4 setup, and the 25 shadcn UI primitives (React components,
      framework-independent)

  DOES NOT CARRY OVER - NEEDS REBUILDING ON THE NEW STACK
    - proxy.ts (Next.js route gate) -> TanStack Start route guards
    - app/layout.tsx, app/page.tsx, App Router file conventions ->
      TanStack Router file routes
    - app/api/auth/[...all]/route.ts and app/api/uploads/route.ts ->
      Hono route handlers
    - next-intl i18n wiring -> a TanStack-compatible i18n approach
    - next/font, next/image -> standard font loading and an image strategy on
      the new stack

  NOTE ON PRISMA
    It is pinned to 6.19.3 because Prisma 7 dropped MongoDB support.
    Keep that pin.
